# v8 검증 계획 — 전체 목표는 진행 중

이 문서는 추가 유료 실행 전에 검토할 범위다. 로컬 검증, GPU 생성 성공,
실패 사례 기록 중 어느 것도 7단계 전체 완료를 뜻하지 않는다.

## 고정 입력과 실행 범위

`QUALITY_EVALUATION_V3.json`의 기존 6장은 개발 자료다. 새 거실·설비실·서재
3장은 생성 결과를 보기 전에 29개 선택 객체(작은 객체 5개), 지지 관계와
공간 보존 조건을 표시했다. 이 주석은 전체 객체 목록이나 실측 3D 정답은 아니다.

추가 제출 상한은 총 13회다. 기존 endpoint `8dzbkfrxys43hb`를 이용한다.

1. 개발: 기존 demo10·demo13·demo15에 v8을 1회씩, 총 3회.
2. 개발 결과 검토를 통과한 경우에만 새 입력 3장 × v4/v5/v8, 총 9회.
3. 품질 판정 후 새 UI와 후보 release를 함께 임시 적용하고, 거실 입력으로
   인증 링크 → 업로드 → 생성 → 표시 → 다운로드 1회. 이 제출도 상한에 포함한다.

애플리케이션 자동 재제출은 하지 않는다. 제출 의도를 POST 전에 저장하고,
응답이 불명확하면 제출 여부부터 확인한다. 플랫폼 자체 재시도는 별도 기록한다.
단계별 실행 후에는 v4로 복원하고 읽어 확인한다. 품질·통합 검증을 모두 통과한
후에만 정식 배포 대상으로 판정하며, 배포에도 사용자 승인이 필요하다.

GPU 종류·개수·image·scaling은 유지한다. release 전환 시 기존 검증과 동일하게
대기·실행 작업이 없는 상태에서 worker를 0으로 내려 이전 프로세스를 정리한 뒤
원래 min 0/max 1/idleTimeout 60으로 복원한다. 관련 없는 작업은 취소하지 않는다.

## 통과 기준

- 이름 제거/변경 시 고정 마스크·메시의 배치, 공간 구조, GLB가 동일해야 한다.
- 동일 입력의 v4/v5와 일대일 상자 대응, 작은 객체 대응, 중복 및 잘못된 이동을
  함께 비교한다. 전체 대응 수의 증가로 작은 객체 손실이나 잘못된 이동을 감추지 않는다.
- 중복 개선은 실제 시각 검토에서도 확인되어야 한다. 형상을 잘라 없애거나 실제
  소품을 삭제한 결과는 실패다. 진열장의 중첩 실패를 명시적으로 재검토한다.
- TV의 벽 부착, 매달린 조명, 선반 위 소품 등 원래 올바른 관계가 보존되어야 한다.
  접촉 이동은 실제 삼각형 근거와 이동량을 기록한다. 열린 메시의 내부 체적은
  확정할 수 없으므로 관통이 없다고 단정하지 않는다.
- 바닥·벽·천장은 관측 근거·신뢰도를 기록하고, 근거가 부족하면 생성하지 않는다.
  열린 통로·창·문을 임의의 면으로 막으면 실패다. 관측 표면은 완전한 방으로 세지 않는다.
- 고정 메시의 변경별 비교와 새 추론 결과를 분리한다. 추론의 비결정성 때문에
  서로 다른 생성 메시의 차이를 모두 보정 알고리즘 효과라고 주장하지 않는다.
- 실제 GLB 객체/공간 부모 그룹, 토글·내부 관찰·기존 v4/v5 표시 및 다운로드
  전체 해시를 확인한다. 로컬 브라우저 통과로 운영 인증/업로드 경로를 대체하지 않는다.

품질 미달이면 v4를 유지하고 원인을 수정한다. 이때 전체 목표를 완료 처리하지 않는다.
새 평가 출력을 보고 구현을 조정하면 해당 입력은 개발 자료로 이동하고 다음 독립
평가에는 새 입력을 선정한다. 추가 유료 실행은 승인된 제출 상한을 넘기지 않는다.

## 비용 근거

2026-10-16 REST catalog에서 A40는 GPU당 시간당 $1.22로 확인했다.
이전 9회 실행 시간 합계는 약 82.13분, 중앙값은 약 6.66분이었다.
같은 중앙값으로 13회를 단순 환산하면 실행 시간 약 1.44시간, 약 $1.76이다.
이는 견적이나 비용 상한이 아니다. 새 탐지 후보 증가, 시작/대기 시간,
플랫폼 재시도 및 실제 청구 조건에 따라 달라질 수 있다.

이전 승인은 9회 제출과 v4 복원으로 한정되었고 이미 사용되었다.
새 비용·추가 제출·정식 배포는 이 계획을 구체적으로 승인받은 뒤 실행한다.
