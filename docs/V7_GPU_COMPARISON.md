# v4 / v5 / v7 실제 GPU 비교

2026-10-16 사용자 승인 범위: 고정 평가 입력 3장 × 3버전 = 9회 제출, 기존 endpoint 임시 전환, 종료 시 v4 복원. 새 GPU 종류나 리소스를 추가하지 않는다. 실행 중인 결과는 완료나 품질 통과로 집계하지 않는다.

## 평가 방법

입력과 25개 선택 객체의 주석은 출력 확인 전에 `QUALITY_EVALUATION_V2.json`으로 고정했다. 이전 실패 3장은 개발 자료로 분리했다. 이 평가는 제한된 2D 상자 주석의 일대일 마스크 대응이며, 전체 객체 재현율이나 정답 3D 정확도가 아니다. 이름은 주석 설명과 화면 표시용이며 대응 계산은 상자의 기하 관계만 사용한다.

버전별 패키지는 `.runtime/v7-gpu-comparison/releases.json`, 제출은 `jobs.json`, 원본 응답은 `<run>-result.json`, 무결성은 `<run>-verified.json`, 대응 평가는 `<run>-annotations.json`에 기록한다. 실제 GLB를 변경하지 않고 Chrome에서 표시·전환·다운로드를 검사한다. 화면 검토 근거는 `visual-review.json`과 각 결과의 `browser.png`에 남긴다.

`scripts/summarize_v7_comparison.py`가 최신 기록을 `summary.json`으로 모은다. 이 스크립트는 시각 품질 통과나 배포 승인을 자동으로 판정하지 않는다.

서로 다른 worker에서 추론을 다시 실행하므로 최종 메시가 비트 단위로 같다는 전제는 두지 않는다. 첫 방 이미지의 v4/v5는 선택 마스크 8개와 초기 포즈가 같았지만 메시 정점·면은 완전히 일치하지 않았다. 따라서 전체 결과 비교와 고정 메시에서 수행한 변경별 CPU 비교를 구분하며, 모든 화면 차이를 배치 알고리즘의 인과 효과로 해석하지 않는다.

## 기준선에서 확인된 실패

- 창이 있는 방: v4는 지정 객체 7개 중 5개 대응, 작은 객체 2개 모두 누락. 큰 방 형태가 원본의 창문을 막고 일부 가구를 가린다. 병·책은 초기 탐지 후보에 없으므로 배치 보정만으로 복구할 수 없다.
- 진열장: v4는 10개 중 4개 대응. 선반·수납장 형태가 중첩되고 일부 접시에 지지면이 보이지 않는다.
- 계단 홀: v4는 8개 중 0개 대응. 전체가 하나의 건축물 덩어리로 생성되어 계단·열린 공간·독립 소품이 보존되지 않는다. 신뢰도 0.914와 0.926의 샹들리에 마스크도 큰 마스크에 포함됐다는 이유로 제거됐다. 제안 단계와 선택 단계의 실패를 구분해야 한다.

v4 세 결과는 파일 무결성·GLB 변환 검증·Chrome 표시와 다운로드 검사를 통과했다. 이 기능 통과는 위 품질 실패를 상쇄하지 않는다.

## 버전별 선택 객체 대응

| 입력 | 선택 주석 수 | v4 | v5 | v7 |
|---|---:|---:|---:|---:|
| 창이 있는 방 | 7 | 5 | 5 | 5 |
| 진열장 | 10 | 4 | 3 | 3 |
| 계단 홀 | 8 | 0 | 6 | 6 |
| 합계 | 25 | 9 | 14 | 14 |
| 작은 객체 부분집합 | 4 | 0 | 1 | 1 |

v5는 계단 홀의 객체 보존이 개선됐지만 진열장에서는 대응 수가 줄었다. 창이 있는 방과 진열장의 접촉 보정은 모두 0건이며, 원래 문제 형상이 화면에 남는다. 객체 수 증가를 공간 복원 성공으로 판단하지 않는다.

v7 첫 방에서도 큰 공간 객체가 남아 창문을 막는다. 별도 구조는 벽 5개·천장 1개 패치이며 바닥은 없다. 작은 객체는 여전히 0/2, 접촉 보정은 0건이다. 진열장은 접시의 원래 기울기를 유지하는 점이 화면에서 개선됐지만 선반 중복과 지지 문제는 남았다. 별도 구조는 작은 벽 패치 1개, 접촉 보정은 0건이다. 보이지 않는 바닥·천장을 만들어내지 않은 것은 적절한 보류이나, 이 벽 조각만으로 공간 경계가 검증되지는 않는다.

계단 홀의 v7도 대응 6/8, 작은 객체 1/2로 v5와 같다. 별도 공간 표면은 0개이며, 큰 건축물 메시가 계단·열린 공간을 대체하는 문제가 남았다. 법선 기반 방향 추정은 근거 부족으로 보류됐다. 기둥 하나를 큰 건축물 메시 위로 올리는 접촉 이동 1건(장면 단위 Y +0.1275865)이 적용됐지만, 지지 메시 자체에 큰 객체와 부분 객체의 중복 문제가 있어 실제 개선이나 무해한 이동으로 판정하지 않았다. 실측 미터 단위 수치가 아니다.

세 v7 결과의 생성 객체 수는 8·12·12이며 중복/공간 후보로 제외된 객체는 0개다. 개발 장면에서의 공간 후보 분리 효과가 이번 평가 입력에서는 확인되지 않았다. **v7의 품질 기준은 실패이며 배포하지 않는다.**

## 배포 브라우저 경로

v4 첫 결과를 기존 인증 링크로 다시 열어 검사했다. 인증 쿠키, 표시, 객체 토글, 카메라 회전, 다운로드 전체 SHA-256, 저장 결과 새로고침을 통과했다. 최초 GLB 범위 요청에서 HTTP 400이 한 차례 있었고 같은 브라우저의 후속 요청은 206으로 성공했다. 원인은 확정하지 않았으며 `.runtime/v7-gpu-comparison/cloud-v4/report.json`에 실패 응답과 후속 성공을 모두 보존한다. 이번 재열기 검사는 추가 GPU 생성을 제출하지 않았다.

v7 첫 결과도 같은 경로의 검사를 통과했다(`cloud-v7/report.json`). 추가 전송 진단(`cloud-v7-range-diagnostic/report.json`)에서는 400 대신 중간 조각의 503·502 응답이 재시도로 복구됐고 최종 다운로드 해시가 일치했다. **간헐적 전송 오류의 원인은 미확정이며 해결됐다고 보지 않는다.** 운영 웹 UI는 변경하지 않았으므로 새 공간 토글·cutaway 검증은 현재 로컬 UI와 실제 GLB 조합의 결과다. 이번 실행은 업로드부터 새로 생성하는 전체 브라우저 검사를 추가로 수행한 것이 아니라, 승인된 GPU 결과를 인증 후 재열기한 검사다.

## 실행 종료와 복원

9회 제출이 모두 실행 성공했고, 9개 결과 모두 입력·release·GLB 해시, GLB 변환 검증, Chrome 표시·다운로드 검사를 통과했다. 새 공간 토글과 cutaway는 공간 표면이 있는 두 v7 결과에서 검사했고, 표면이 없는 결과와 v4/v5의 기존 표시도 확인했다. 오류 없는 생성과 품질 성공은 구분한다.

2026-10-16 03:48 KST 운영 release를 v4 `47fb1a517a24e0d1b32e13fa1ad1f5cf3502696dcf947c591006cb77f4069fbb`로 복원했다. `rollback-result.json`에서 전체 환경 변수·worker 복원, GPU·scaling·image 유지가 확인됐다. 별도 `post-restore-readback.json`에서도 release/key·환경 변수 digest·worker min 0/max 1/idleTimeout 60 일치와 진행·대기 작업 0건을 재확인했다. 복원 후 추가 GPU 추론은 실행하지 않았다.

실행기는 추가 제출이나 자체 재시도를 하지 않았다. v5·v7 첫 작업에는 각각 Runpod의 플랫폼 재시도 1회가 기록되어 있으며 원본 응답을 보존했다. 같은 평가 출력에 맞춰 규칙이나 임계값을 다시 조정하지 않았다. 판정은 `.runtime/v7-gpu-comparison/deployment-decision.json`의 `FAIL_KEEP_V4`이다.
