2. 실험을 읽는 기준

  • GPU 추론 비교: 이미지에서 마스크·메시를 다시 생성한다. 시드·입력이 같아도 메시가 완전히 같지 않을 수 있어, 후처리 하나의 인과 효과로 해석하지 않는다.
  • 고정 자산 CPU 비교: 같은 마스크·메시·pointmap으로 특정 보정만 바꾼다. 해당 보정의 효과를 분리하는 데 유용하지만 검출 성능이나 실제 GPU 전체 경로를 검증하지 않는다.

6. 왜 오래 걸렸고 무엇이 비효율적이었나

  1. 국소 지표 개선 뒤에 전체 관계 검사를 붙였다. 재생성·깊이·접촉이 좋아 보인 뒤 주변 접촉 손실이나 원본 광선 누락을 발견해 후보를 다시 버렸다. v17과 v25~28, 집 수납장 대안이 대표적이다.
  2. 통합 보존 검사의 누락을 늦게 찾았다. 앞선 자세 단계에는 뒤쪽 지지 보정과 같은 원본/기존 지지 검사가 없었다. 수정 후 전체 재생을 다시 해야 했다. 실행 중 변경된 소스와 동결 버전을 구분하는 작업도 늘어났다.
  3. 완료 판단에 유용한 실험보다 진단을 계속 확장했다. 안전하게 거부하는 이유·테스트 수는 늘었지만, 지지 관계가 실제 개선된 최종 장면은 확보하지 못했다. 진단 완료를 품질 진전처럼 보고하면 안 됐다.
  4. 검증 비용이 컸다. 수백 MB~GB의 산출물, 천만 단위 삼각형, 반복적인 정확 거리·교차 계산, 전체 장면 재생으로 시간이 길어졌다. 작은 벤치마크의 속도 개선을 전체 실행 시간 개선으로 환산할 수 없었다.
  5. 실행·전송 문제도 있었다. 초기 전송 규칙·변수 오류, 실행 중 소스 일관성 문제, GPU 2시간 제한 실패, 최근 Runpod 이미지 인증 실패가 있었다. 이 시간은 품질 개선에 사용된 시간과 구분해야 한다.
  6. 비용을 보여주는 정리가 늦었다. 최근 실행 기록 기준 확인된 제출은 266건이다. 이전 기록에는 전체 장면 생성뿐 아니라 부분 비전/진단 작업이 섞여 있다. 266건 모두가 전체 생성도, 성공도 아니다. 토큰 기록·GPU 제출 수·실제 청구액을 같은 비용 수치로 섞어서는 안 된다. 이 문서에서는 정확한 청구 합계를 재계산하지 않았다.

요청 수에서 큰 비중을 차지한 것은 영상 관계 모델이다. 해당 시점의 기록은 219요청 = 장면/기타 진단 계열 23 + 영상 관계 질의 196으로 구분한다. 영상 관계 질의는 40 + 52 + 52 + 52회이며, 각각 전체 3D 장면 생성은 아니다. 모델을 바꾸거나 질문 표현을 바꿔도 안전한 자동 삭제에 도달하지 못했다. 이 실험을 생략하면 266회라는 숫자의 의미와 소요 원인을 제대로 설명할 수 없으므로 별도로 남긴다.

테스트가 수백 개 통과했다는 사실은 구현 회귀를 줄였다는 뜻이다. 사용자가 원하는 장면 품질을 달성했다는 뜻은 아니다. 최근 기본 환경 실행은 518 passed, 6 skipped였다. 과거 native-enabled 실행의 535 등과 환경/시점이 다르므로 하나의 연속 품질 점수로 제시하지 않는다.

8. 다음에 개발을 재개할 때의 판단 기준

지금 자료로는 '가장 최신 버전을 그대로 배포'하는 결론을 낼 수 없다. 집 v53·사무실 v49를 현재 비교 기준으로 보존하고, 다음 시도는 실제 실패 관계 하나를 대상으로 원본 보존·기존 접촉·새 관통을 동시에 평가해야 한다. 같은 방식이 다른 개발 장면에서도 개선을 만들 때 전체 재생으로 넘어가는 것이 낫다.

객체 위치만 고치는 접근은 원래 생성된 다리·밑면·받침 형상이 틀리면 한계가 있다. 그렇다고 형상을 재생성하면 주변 관계가 손상될 수 있으므로, 재생성 후보 선택에도 장면 관계 검사가 필요하다. 이미 실패한 전역 깊이 강화·배경 중립화·무조건 개수 상향·단순 접지 이동을 같은 형태로 반복할 근거는 없다.

이 절은 검토 후 재개할 때의 제안이며, 보고서 작성 중 새로운 생성 실험을 실행했다는 뜻이 아니다.
