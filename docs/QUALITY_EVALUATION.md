# v6 검증 기준

> 이 문서는 v6 당시 고정한 기준과 결과를 보존한 기록입니다. 아래의 ‘새 입력’, 제출 횟수와 ‘다음 변경’은 당시 시점을 가리킵니다. 현재 개발·미사용 평가 분리는 [V3 평가 명세](QUALITY_EVALUATION_V3.json), 집·사무실·식당의 후속 개발 주석은 [개발 주석](QUALITY_DEVELOPMENT_ANNOTATIONS.json), 현재 구현과 검증 상태는 [진행 기록](V10_LOCAL_PROGRESS.md)을 따릅니다. 세 원래 입력은 이미 결과를 본 개발 자료이며 현재 미사용 평가 자료가 아닙니다.

이름 없는 기하 보정과 관측 공간 표면 복원의 평가다. 객체 수 증가는 정확도 향상으로 취급하지 않는다. 운영 v4는 검증 중 임시 적용을 제외하고 유지한다.

## 고정 입력

`QUALITY_EVALUATION_MANIFEST.json`은 기존 실제 추론 22개 장면의 원본 GLB·메타데이터 해시와 공개 평가 입력 3장의 출처·해시를 기록한다. 기존 장면은 이미 본 회귀 자료이며 일반화 평가용으로 부르지 않는다.

새 입력은 Microsoft MoGe 저장소의 고정 revision `74fbce054ebed49800de42d0ad0e83495065719a`에서 받은 집·사무실·식당 예제다. 로컬 사본은 Git 제외 경로에 보관한다. 세 입력의 출력은 보정 임계값 조정에 사용하지 않는다. 실패를 발견하면 이번 평가를 실패로 기록하고, 후속 변경은 다른 미사용 입력으로 다시 평가한다.

## 검증 층

| 층 | 확인 내용 | 해석 제한 |
|---|---|---|
| 합성 기하 | 이름 제거·변경 불변성, 크기 변경, 빈 지지면, 모호한 접촉, 실제 폐곡면 내부 표본, 벽 접촉, 공간 평면·내보내기 | 실제 추론 모델 정확도는 측정하지 않음 |
| 저장 결과 22장 | 원본 불변, 변환·bounds 재로드, v6 재실행 동일성, 이름 제거 결과 일치 | 원본에 pointmap이 없어 공간 추정·깊이 중복 판별은 평가 불가 |
| 공개 입력 3장 | 실제 GPU 실행, 공유 pointmap 프레임·해시, 공간 표면, 객체·접촉의 화면 검토 | 소수 입력이며 정답 깊이·마스크가 없어 정량적 일반화·재현율 결론 불가 |
| 브라우저 | 실제 WebGL, 공간 전체/유형별 전환, cutaway, 객체 전환, 다운로드 동일성 | 기하학적으로 올바른 복원이라는 증명은 아님 |

## 출력 확인 전에 고정한 화면 검토 항목

- 집: 바닥·벽·천장이 보인다. 벽걸이 TV와 벽 장식, 테이블 위 화분, 좌석·발판이 있다. TV를 바닥으로 내리거나 화분을 잎 전체 너비 때문에 옮기는지 확인한다. 천장 팬을 천장 평면으로 메우면 실패다.
- 사무실: 바닥·벽이 보이며 천장은 보이지 않는다. 책상 위 타자기·램프, 선반 위 축음기, 별도 받침의 지구본이 있다. 천장을 임의 생성하거나 책장·책상 부품을 중복 추출하는지 확인한다.
- 식당: 여러 층, 계단, 곡면 난간, 기둥, 샹들리에가 있는 어려운 입력이다. 단일 상자 방을 강제하면 실패다. 계단·다층 바닥을 하나의 평면으로 메우지 않아야 하며, 불확실한 영역을 보류하는 것은 허용한다.

검토 항목은 사람이 알아볼 설명일 뿐 보정 코드의 클래스 목록으로 전달하지 않는다. 현재 pixel-level 정답 마스크와 실측 공간 치수는 없다. 누락률·중복률·지지 정확도의 수치를 발표하려면 별도 정답 주석과 대응 객체 매칭을 먼저 준비해야 한다.

## 재현

```powershell
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/python.exe scripts/evaluate_scene_quality.py --output .runtime/v6-validation/replay-new
node scripts/verify_room_viewer.mjs <saved-run-directory>
```

`evaluate_scene_quality.py`는 GPU 작업을 제출하지 않는다. 출력 디렉터리를 새로 지정해야 원본과 이전 결과를 덮어쓰지 않는다. 실제 GPU 검증은 승인된 이미지 3회만 제출하고 release 해시와 job ID를 기록한다. 운영 복원은 원래 release key·hash와 worker 설정을 재조회하여 확인한다.

## 배포 기준

코드·GLB·UI 검증 통과만으로 정식 배포하지 않는다. 실제 GPU 어댑터가 동작하고, 화면 검토에서 중대한 잘못된 이동·허위 공간 표면이 없으며, 기존 동작의 회귀가 없는지 확인한다. 근거가 부족하면 v4를 유지하고 v6는 실험 구현으로 남긴다.

## 실제 검증 결과 — 2026-10-16

승인받은 공개 입력 3장만 GPU로 실행했다. release SHA-256은 `2a4864954f0d342a3964bc1a1008f52916d34d08f456d58918c95288bef96009`다. 모두 12개 객체 생성, 산출물 무결성·좌표 합성 검사, Chrome WebGL 표시·객체/공간 전환·cutaway·다운로드 바이트 일치를 통과했다. 새 공간 UI는 저장 결과를 사용하는 로컬 뷰어에서 검사했다. 운영 웹 UI에는 배포하지 않았다. 집 결과는 기존 비공개 클라우드 인증·표시·다운로드·다시 열기 경로도 통과했다.

세 장 모두 깊이 기반 중복 제외와 접촉 보정이 0건이었다. 보수적인 기하 조건이 실제 생성 메시에서는 작동하지 않아, 이번 결과로 중복·지지 관계 개선을 입증하지 못했다. 단일 상자 방을 강제하지 않은 것은 확인했지만 공간 전체 복원은 미달이다. 이 출력에 맞춰 임계값을 변경하지 않았다. 테스트 89개 및 저장 장면 22개·객체 120개의 회귀 통과와 실제 품질 실패를 구분한다.

세 작업 완료 직후 v6 worker가 0개가 된 것을 확인하고, 원래 v4 release `47fb1a517a24e0d1b32e13fa1ad1f5cf3502696dcf947c591006cb77f4069fbb` 및 worker(min 0 / max 1 / idleTimeout 60) 설정을 복원했다. API 재조회로 전체 env·workers 일치와 GPU·scaling·image 불변을 확인했다. 복원 후 추가 추론은 실행하지 않았다.

증거: `.runtime/v6-validation/jobs.json`, `live/<run>/browser-report.json`, `visual-review.json`, `rollback-result.json`, `replay/report.json`. `scripts/preview_saved_results.py --results .runtime/v6-validation/live`는 저장 결과만 제공하고 생성 POST를 거부한다.

후속 작업은 이름을 추가하는 대신 장면 전체/재질 부분 마스크를 기하적으로 구별하는 객체성 검증, 열린 고밀도 메시에도 적용 가능한 접촉 검사, 객체 pose에 덜 의존하는 공간 방향 추정이다. 변경 후에는 다른 미사용 입력과 정답 주석으로 평가해야 한다.

## 후속 구현 1 — 후보 재검토·접촉 거절 사유

이름·이미지별 좌표를 사용하지 않는 후보 재검토를 추가했다. 부모 마스크가 서로 닿지 않는 여러 자식 마스크의 **정확한 합집합**이고, 각 자식에 충분한 유효 깊이가 있으며 깊이 구간이 분리될 때만 부모를 중복 제외한다. 남은 연결 픽셀, 겹치는 자식, 같은 깊이, 불완전한 깊이가 있으면 보류한다. 제외된 부모를 대신하는 자식은 후속 부분 중복 검사에서 보호한다. 작은 포함 물체는 크기만으로 제거하지 않는다. 연결된 방 전체 마스크·재질 부분을 일반적으로 해결하는 객체성 모델은 아직 아니다.

`placement.contacts.rejections`에 객체·후보·검사 단계·거절 이유를, `rejection_counts`에 이유별 건수를 기록한다. 검사 지점 부족, 밑면 크기, 이동 한도 등에는 수치 근거도 포함한다. 벽 검사는 아직 복합 조건의 상세 분리 없이 근거 부족으로 기록한다. `no_supported_candidate`는 후보별 거절과 별도의 객체별 결과이므로 전체 건수를 실패 객체 수로 해석하면 안 된다.

기존 GPU 결과 3장을 원본 변경 없이 다시 진단했다. 새 GPU 실행이나 운영 변경은 없었다. 이번 규칙의 자동 중복 제외는 세 장 모두 **0건**으로, 실제 품질 개선은 아직 입증하지 못했다.

| 거절 이유 (후보별 건수) | 집 | 사무실 | 식당 |
|---|---:|---:|---:|
| 밑면이 지지 후보보다 넓음 | 32 | 32 | 0 |
| 검사 지점에 실제 지지 삼각형 없음 | 50 | 49 | 66 |
| 지지 높이 불균일 | 1 | 1 | 0 |
| 지지 이동 한도/높이 조건 불충족 | 0 | 2 | 0 |
| 제3 객체 경계 상자와 겹침 | 0 | 1 | 0 |
| 벽 접촉 근거 부족 | 36 | 48 | 60 |

테스트 **99개 통과**: 새 합집합 중복 제외, 연결 부분·깊이 모호성 보존, 크기/순서/이름 독립성, 자식·마스크 파일 보존, 접촉 거절 기록을 포함한다. 이번 진단은 이미 본 실패 입력의 분석이며 새 일반화 평가가 아니다. 이전 22장면 회귀 결과와도 별개다. 원본 GLB·메타데이터·pointmap 해시 불변을 확인했다. 보고서는 `.runtime/candidate-audit-v1/`에 저장했다.

```powershell
.venv/Scripts/python.exe scripts/audit_saved_candidates.py <saved-run-1> <saved-run-2> --output <new-output-directory>
```

다음 변경은 다섯 수직 검사점과 밑면 사각형에 의존하는 지지 판정을 실제 접촉 표면 중심으로 바꾸는 작업이다. 겹침을 우려해 모든 이동을 거절하는 경계 상자 검사도 실제 표면 검사와 분리해야 한다. 현재 단계에서 임계값을 완화하거나 운영에 배포하지 않는다.
