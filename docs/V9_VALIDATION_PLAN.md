# v9 후보와 남은 완료 기준

> 최신 결과: v9r2 개발 GPU 3회와 산출물·Chrome 검증 완료. 대응 23/25로 개선됐으나 품질 미달이며 운영 v4 복원 확인. 전체 7단계는 미완료다. [최종 비교 기록](V9_GPU_COMPARISON.md)을 우선 참고한다. 아래는 후보별 계획·실행의 이력이다.

2026-10-16. 운영은 v4이며 v9는 로컬 후보다. v8의 개발 GPU 3회는 완료했지만 품질 기준에 실패했다. 단계 7의 통합 품질 통과나 배포 완료로 간주하지 않는다.

## 실패 원인과 수정

- v8은 150개 이상의 유효 프롬프트가 있어도 40개만 분할했다. v9는 유효 프롬프트를 전부 분할하고 원본 마스크 후보를 보존한다. 생성 상한은 12개에서 32개로 늘렸다. 상한 초과와 저신뢰도 탈락은 여전히 가능하며, 재현율 개선은 새 GPU 실행 전에는 미검증이다. 분할·생성 시간과 요금이 증가할 수 있다.
- 희소하고 화면을 넓게 차지하는 다중 평면 마스크가, 원본 시점에서 과도하게 채워진 생성 메시와 함께 확인될 때 관측 표면으로 전환한다. 이름을 사용하지 않는다. 숨겨진 공간을 발명하지 않으며 방 종류를 확정하지 않는다. 단순히 큰 객체나 가려진 객체라는 이유로 제거하지 않는다.
- 복합 객체의 메시가 원본 마스크와 크게 불일치할 때만 중복 제거를 검토한다. 독립 자식들의 마스크·메시가 보이는 영역을 유지해야 하며, 설명되지 않는 작은 연결 영역이 남으면 보류한다. 기존 12개 객체의 전시장 결과에서는 제거 조건을 충족하지 않아 중복이 아직 남는다.
- 이미 그룹화된 GLB를 재처리할 때 이전 부모 간선이 남는 오류를 수정했다. 모든 월드 변환을 보존하면서 부모 그래프를 재구성하고, 다시 가져온 GLB의 단일 부모와 그룹 구분을 검사한다.

이 보정들은 객체 이름을 읽지 않는다. 탐지 모델의 언어 프롬프트와 이름 표시는 별도이며, 탐지 단계의 기존 후보 필터가 모두 제거되었다는 의미는 아니다.

## 로컬 검증과 한계

단위·회귀 테스트 184개와 새 실행기 경계 테스트 5개가 통과했다. 개발 장면 6개의 재처리에서 원본 보존·멱등성과 실제 GLB 그룹/변환 검사가 통과했다. 6개 장면 모두 실제 Chrome 표시·전환·바이트 일치 다운로드 검사를 통과했다. 변경별 비교 24개도 완료했으며 6개 장면 모두 이름 제거 시 GLB 바이트와 판단이 동일했다. 결과는 `.runtime/v9-development/fixed-groups-replay` 및 `fixed-groups-ablation`에 기록한다.

이전 `projection-routing-replay`, `earlier-scene-regression`, `combined-replay`, `ablation` 결과는 부모 그래프 오류 수정 전 결과이므로 최종 검증 근거에서 제외했다. 목록과 이유는 `invalidated-replays.json`에 보존했다.

최종 변경별 비교는 개발 장면 6개에 대해 결합 구현, 이름 제거, 투영 기반 공간 전환 제외, 복합 메시 검토 제외의 4가지다. 이름 제거 결과는 GLB 바이트와 배치·공간·중복 판단이 동일해야 한다. 저장된 결과 재처리는 새 마스크와 새 객체를 생성하지 않으므로 32개 상한의 효과를 입증하지 않는다.

고정 후보 SHA-256: `66b926af2f1715e1b53b42a6060df7297b43f0326869e0dfbfff0ddf67753f78`. `.runtime/v9-release/application.zip`은 아직 업로드·배포하지 않았다. 실행기의 개발 3회·평가 9회 dry-run과 승인 누락/품질 실패/중복 제출 차단 테스트가 통과했다.

## 승인 및 실행 상태

사용자가 총 16회 범위를 승인했다. v9 개발 단계는 2026-10-16 06:33:44 UTC에 기존 endpoint의 고정 후보 해시를 읽어 확인한 뒤 시작했다. `.runtime/v9-gpu-comparison/approval.json`에 승인과 상한을 기록했다. 각 단계 종료 후 v4 복원, 품질 통과 시에만 다음 단계 실행 조건을 유지한다.

## 승인된 실제 검증 범위

기존 승인은 고정 v8 후보에 대한 총 13회였다. 그중 개발 3회가 사용되었고 미사용 평가 9회와 인증 브라우저 1회는 실행하지 않았다. v9 개발 3회를 추가하고 평가 9회·브라우저 1회를 유지하면 이번 검증 묶음은 **기존 사용 3회를 포함하여 최대 16회**가 된다. 새 후보·추가 3회는 승인되었으며, 총 16회 상한을 넘는 제출은 하지 않는다. 기존 승인 파일을 수정하거나 자동 재시도하지 않는다.

1. 고정 v9로 기존 개발 이미지 3장 실행 후 v4 복원. 작은 객체, 중복, 잘못된 이동, 접촉·관통, 공간 근거를 개별 평가한다. 전시장의 대응 감소 등 장면별 퇴행을 전체 평균으로 상쇄하지 않는다.
2. 개발 품질 통과 시에만 아직 미사용인 V3 평가 3장 × v4/v5/v9, 총 9회. 입력·주석·후보 해시를 고정하고 같은 기준으로 비교한다.
3. 평가 품질 통과 시 인증 → 업로드 → 생성 → 표시 → 다운로드 1회. 실제 운영 정적 파일과 GLB 그룹·표시 제어를 함께 확인한다.
4. 전체 기준 통과 시에만 승인 범위의 배포를 진행한다. 실패하면 운영 v4를 유지하고 실패 사례와 원인을 기록하며 수정 작업을 계속한다.

GPU 종류·자원 수는 늘리지 않는다. 기존 endpoint와 설정을 기록하고 단계 종료 후 복원한다. 후보 32개 상한 때문에 v8 실행 시간으로 비용 상한을 보장할 수 없다.

## 7단계 완료까지 남은 증거

| 단계 | 남은 완료 증거 |
|---|---|
| 평가 기준 | 미사용 V3 세트의 v4/v5/최종 후보 결과와 같은 주석 기준 비교 |
| 이름 의존 제거 | 최종 후보의 이름 제거 불변성 결과 확정 |
| 중복 개선 | 새 GPU 결과에서 실제 중복 감소와 작은 객체 보존 확인 |
| 공간 복원 | 평면 근거·신뢰도·보류가 타당한지 평가; 현재 공간 연속성은 미완성 |
| 지지·관통 | 접촉 개선과 원래 올바른 배치 보존; 열린 메시의 체적 불확실성 유지 |
| 뷰어·내보내기 | 실제 배포 경로에서 그룹·전환·기존 결과 호환성 확인 |
| 통합·배포 | 변경별 비교, 미사용 GPU 평가, 인증 브라우저 경로, 품질 통과 후 배포 |

변경별 비교에서는 투영 기반 공간 전환이 sunroom의 과잉 생성 형상을 바꿨으며, 복합 메시 검토는 기존 6장면 모두 조건 부족으로 제거를 보류했다. 중복 개선을 입증한 것으로 보고하지 않는다.

## 전송 오류 수정 (v9r1)

v9 첫 개발 작업 `50d4b39d-bc44-4355-8af0-ab2b706dba55-e1`은 새 루트 파일 `mask_candidates.json`이 기존 산출물 허용 목록에 없다는 오류를 발견하여 취소했다. CANCELLED를 다시 읽었고 06:36:12 UTC에 운영 v4·환경·worker 설정 복원을 확인했다. 개발 품질 결과는 얻지 못했으며 평가·브라우저 GPU 제출도 하지 않았다. 이 취소 제출도 사용량 1회로 센다.

후보 목록을 `masks/candidates.json`으로 옮겨 기존 전송 경로를 사용한다. 생성 상한을 넘는 40개 마스크와 목록을 실제 pack/unpack한 뒤 내용·해시를 확인하는 회귀 테스트를 추가했다. 전체 190개 테스트가 통과했다. 기하 보정 코드는 변경하지 않았으므로 앞서 완료한 6장면·24가지 비교 증거는 유지된다.

수정 후보 SHA-256은 `4c960b166b8c7c3774465a2bf9f58a91b871965ddc9654e04b0f6c72e8a35e36`이다. `.runtime/v9r1-release/application.zip`으로 별도 보존했으며 아직 업로드·실행하지 않았다. 기존 승인 기록과 취소 실행 기록은 덮어쓰지 않는다. 개발 3회·평가 9회·브라우저 1회를 유지하려면 앞서 사용한 4회를 포함하여 총 17회가 필요해, 추가 1회 범위 승인을 요청했다.

사용자가 총 17회 상한을 승인했다. 수정 후보 적용은 06:38:24 UTC에 읽어 확인했고 개발 첫 작업을 제출했다. 승인·실행·복원 기록은 `.runtime/v9r1-gpu-comparison`에 별도로 보존한다.

## 실제 분할 실패와 v9r2 수정

v9r1의 첫 작업은 GPU에서 150개 후보 분할을 마쳤으나, 함수 추출 때 남은 `candidate_records` 참조로 로그 작성 중 NameError가 발생했다. 3D 생성 전 실패했고, 산출물 전송은 성공해 실제 마스크와 로그를 보존했다. 06:46:38 UTC에 v4·환경·worker 설정 복원을 읽어 확인했다. 제출 1회가 추가 사용되어 누적 5회다. 평가와 브라우저 생성은 시작하지 않았다.

실제 회수 마스크 14개로 후처리 전체를 로컬 재현하여 변수 참조 오류를 수정하고 목록·객체 9개·로그·미리보기·압축·복원을 검증했다. 하지만 마스크 대응은 5/7, 작은 객체 0/2로 그대로였다. 이는 3D 품질 평가가 아니며 후보 확대만으로 작은 객체 문제가 해결되지 않았다는 증거다.

v9r2는 전체 이미지에서 큰 유효 마스크가 없는 프롬프트를 해당 RAM 탐지 확대 영역에서도 SAM3로 분할한다. crop 경계에서 잘린 조각은 보류하고 원본 크기의 마스크로 되돌려 같은 기하 중복 선택을 적용한다. 이름은 탐지 프롬프트 연결에만 쓰며 의미별 규칙을 추가하지 않는다. 동일 종류의 큰 객체와 작은 객체가 동시에 있을 때는 큰 마스크가 확대 검사를 억제할 수 있다는 한계가 남는다. 첫 개발 이미지에서 추가 14영역·486프롬프트가 계획되어 분할 시간은 더 증가한다.

전체 실행 진입점에 GPU 모델만 대체한 테스트를 추가하여 다중 영역 분할부터 최종 저장·전송까지 확인했다. 총 194개 테스트 통과. 기하 보정 코드는 불변이다. 고정 후보는 `f0a8587ba5fcd3b09012f97788920bebe90bc5db03d09ae9a8cdbcdfbb49e0d9`, `.runtime/v9r2-release/application.zip`이며 아직 업로드하지 않았다.

사용자가 승인한 총 17회 안에서 계속한다. 누적 사용 5회 이후 개발 3회와 평가 API 8회, 평가 겸 인증 브라우저 1회를 실행한다. v9 거실 평가를 실제 인증 업로드 경로로 실행하여 평가 3장×3버전과 브라우저 생성 검증을 모두 충족하고 중복 생성을 피한다. 추가 제출 상한은 12회이며 실행기는 해당 평가 셀을 API 제출에서 제외한다. 개발 품질 통과 조건과 단계 종료 시 v4 복원은 유지한다.
